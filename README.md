# Пермэнергосбыт — передача показаний (Home Assistant)

Кастомная интеграция для Home Assistant, которая раз в месяц автоматически
передаёт показания электросчётчика в личный кабинет
[«Пермэнергосбыт»](https://lk.permenergosbyt.ru/), используя те же значения,
что уже лежат в ваших сенсорах HA (Т1/Т2).

## Куда ходит интеграция

Интеграция обращается к тому же публичному эндпоинту, который использует
форма передачи показаний без авторизации на сайте Пермэнергосбыта:

- Страница-источник: <https://lk.permenergosbyt.ru/personal/measure_without_auth>
- Фактический запрос: `POST https://lk.permenergosbyt.ru/bb/ShowProc2/web.lk_redirect_measure_without_auth`

Никакого официального/документированного API не существует — это
реверс-инжиниринг публичной веб-формы (см. `PROGRESS.md` в репозитории,
если он у вас сохранён локально). Авторизация не требуется — как и на
сайте, доступ к лицевому счёту происходит по его номеру.

## Что делает интеграция

- Раз в месяц, в заданные вами день/час/минуту, читает текущие показания
  из двух указанных вами сенсоров HA (Т1 «день» и Т2 «ночь») и отправляет
  их на сайт.
- Если сайт недоступен или вернул ошибку — повторяет попытку: 3 раза с
  интервалом 2 часа в плановый день, и если не помогло — ещё 3 раза с
  интервалом 2 часа на следующий день. Если и это не сработало —
  присылает уведомление в Home Assistant (Настройки → Уведомления).
- Даёт кнопку **«Передать показания сейчас»** и сервис
  `permenergosbyt.send_readings` — для ручного разового запуска (например
  теста) без ожидания расписания. Ручной запуск не повторяется при ошибке,
  сразу сообщает о результате.
- Сервис поддерживает параметр `dry_run: true` — показания не отправляются,
  только пишется в журнал HA, что было бы отправлено (для проверки, что
  всё настроено правильно, без риска).
- Даёт сенсор **«Статус последней отправки»** (`sensor.<...>_status_poslednej_otpravki`)
  со значением «Успешно» / «Ошибка» / «Ещё не отправлялось» и атрибутами
  `last_attempt_at`, `last_success_at`, `last_error` — быстрый способ
  посмотреть результат без чтения журнала. Учитывает только реальные
  попытки (плановые и ручные), `dry_run` на него не влияет.

## Установка

### Вручную

1. Скопируйте папку `custom_components/permenergosbyt/` в
   `<конфиг Home Assistant>/custom_components/permenergosbyt/`.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → Добавить интеграцию → «Пермэнергосбыт».

### Через HACS

Репозиторий подготовлен для установки как пользовательский (custom) в
HACS — `hacs.json` в корне и заполненные поля `manifest.json`. Пока не
входит в официальный список HACS, поэтому добавляется вручную:

1. HACS → «⋮» (три точки) → Custom repositories.
2. Вставьте URL этого репозитория, категория — Integration.
3. Найдите «Пермэнергосбыт» в списке интеграций HACS и установите.
4. Перезапустите Home Assistant, затем добавьте интеграцию как обычно
   (Настройки → Устройства и службы → Добавить интеграцию).

## Настройка

Установка — в два шага:

1. **Лицевой счёт** (10-11 цифр) — проверяется сразу через реальный запрос
   к сайту; если счёт не найден, форма не даст продолжить. Интеграция
   сама узнаёт по ответу сайта, сколько у счётчика тарифов — вводить это
   вручную не нужно.
2. **Сенсоры с показаниями и расписание** — на этом шаге показывается
   ровно столько полей выбора сенсора, сколько тарифов реально есть у
   вашего счётчика (1, 2 или 3), с их названиями с сайта (например «Т1
   (день)», «Т2 (ночь)»). Плюс день месяца, час и минута ежемесячной
   отправки — по умолчанию 20-е число, 09:00. Перед сохранением
   интеграция сама, тихо, проверяет, что каждый выбранный сенсор
   существует и отдаёт число — если нет, форма покажет ошибку с
   конкретной сущностью и не даст сохранить неверную привязку (не нужно
   отдельно гонять `dry_run` только ради этой проверки).

   > **Важно:** выбирайте дату отправки не менее чем за 2 дня до окончания
   > срока приёма показаний в вашем регионе. Это нужно, чтобы: (1) при
   > сбое сайта успели пройти все автоматические повторные попытки
   > (растянуты на срок до 2 дней), и (2) если и они не помогут — у вас
   > осталось время передать показания вручную до дедлайна.

Расписание и привязку сенсоров к тарифам можно поменять позже без
переустановки интеграции — кнопка «Настроить» на карточке интеграции; та
же тихая проверка сенсоров срабатывает и здесь. Сам набор тарифов
(сколько их и какие) там не меняется — он определяется один раз при
установке по данным сайта и соответствует реальному счётчику, поэтому
пересматривать его не требуется. Лицевой счёт менять после установки
нельзя — для другого счёта нужно добавить интеграцию заново.

## Иконка

Файлы иконки лежат в `brands/permenergosbyt/` (`icon.png` 256×256,
`icon@2x.png` 512×512) — оригинальный дизайн (не логотип компании), просто
чтобы не выглядело как имитация чужого бренда.

Home Assistant не показывает иконки из папки `custom_components` напрямую —
они подтягиваются из отдельного репозитория
[home-assistant/brands](https://github.com/home-assistant/brands). Чтобы
иконка появилась в UI HA и в HACS, файлы из `brands/permenergosbyt/` нужно
отправить туда Pull Request'ом в `custom_integrations/permenergosbyt/`.
Без этого шага HA покажет стандартную generic-иконку интеграции — это не
мешает работе, просто выглядит менее узнаваемо.

## Известные ограничения

- Реальная отправка показаний (`action=save_measure`) через кнопку
  «Передать показания сейчас» подтверждена вживую — показания дошли и
  проверены на сайте личного кабинета. Автоматическая отправка по
  расписанию (включая повторные попытки при сбое) использует тот же код
  отправки, но отдельно на реальном сбое пока не проверялась. Точный
  маркер успеха/неудачи в ответе сервера при ошибке (не при успехе)
  также не подтверждён вживую — если сайт вернёт ошибку не так, как
  предполагает код, это может быть распознано неверно.
- **Поддерживаются одно-, двух- и трёхтарифные счётчики (Т1/Т2/Т3).**
  Счётчики с более чем тремя тарифами не поддерживаются. Число тарифов не
  вводится вручную — интеграция сама определяет его по ответу сайта на
  первом шаге установки, так что попасть в ситуацию «настроил неправильно
  и отправка тихо не работает» невозможно.
- Нет капчи и CSRF-токена в используемой форме на момент разработки — если
  сайт добавит защиту от автоматических запросов, интеграция перестанет
  работать без обновления.

## Тестирование

```
python3 -m venv .venv
.venv/bin/pip install -r requirements_test.txt
.venv/bin/python -m pytest tests/ -v
```

Покрыто модульными тестами (без реального Home Assistant — файлы
компонента загружаются напрямую через `importlib`, минуя
`custom_components/permenergosbyt/__init__.py`):

- `api.py` — парсинг HTML-формы сайта (на реальных, захваченных с
  lk.permenergosbyt.ru образцах в `tests/fixtures/`, для 1/2/3-тарифных
  вариантов) и HTTP-клиент (`fetch_measure_form`/`submit_measures` —
  через самодельные fake-объекты вместо `aioresponses`, которая на
  момент разработки была несовместима с актуальной версией `aiohttp`).
- `const.py` — чистые функции `resolved_schedule`/`resolved_tariff_entities`/
  `device_info` (нужен минимальный stub для `homeassistant.config_entries`/
  `homeassistant.helpers.device_registry`, если полный пакет `homeassistant`
  не установлен — см. `tests/conftest.py`).

Логика в `scheduler.py`, `config_flow.py`, `sensor.py`/`button.py` пока
не покрыта — там нужен `pytest-homeassistant-custom-component` с реальным
тестовым `hass` (таймеры, `Store`, dispatcher, config flow). Как и раньше:
тесты проверяют, что наш код делает то, что задумано, при заданном ответе
сайта — не то, что сайт реально себя так ведёт (маркер успеха/неудачи в
ответе на `save_measure` по-прежнему не подтверждён вживую).
